# RRTS Demo: ระบบรับงานซ่อมและติดตามสถานะ (เว็บ static)

เดโมของระบบรับงานซ่อมที่ใช้งานได้จริงทุกหน้าจอ โดยไม่มีเซิร์ฟเวอร์ ใช้หน้าจอชุดเดียวกับระบบจริง แต่ทุกคำขอ `/api` จะถูกตอบโดย backend ที่รันอยู่ในเบราว์เซอร์ (`src/demo/`) ซึ่งพอร์ตกฎ สิทธิ์ การตรวจข้อมูล และข้อความแจ้งเตือนภาษาไทยมาจากเซิร์ฟเวอร์ NestJS ทีละบรรทัด

ข้อมูลเก็บใน IndexedDB ของเบราว์เซอร์ผู้เปิด แต่ละคนเห็นร้านตัวอย่างของตัวเอง แก้อะไรก็ไม่กระทบคนอื่น กดรีเซ็ตข้อมูลจากแถบด้านบนได้ทุกเมื่อ

## ลองอะไรได้บ้าง

- หน้าเริ่มต้นเลือกบทบาทได้ 4 บัญชี (เจ้าของร้าน หน้าร้าน ช่าง 2 คน) รหัสผ่านทุกบัญชี `demo1234`
- ร้านตัวอย่างมีงานครบทุกสถานะ กับประวัติงานที่ส่งมอบแล้ว 4 สัปดาห์ ให้รายงานมีตัวเลขจริง
- เปิดหน้าลูกค้าในแท็บใหม่ กดอนุมัติราคา แล้วกระดานงานในอีกแท็บจะย้ายงานไปกำลังซ่อมเอง (BroadcastChannel)
- รับเครื่องพร้อมรูปและลายเซ็น ใบเสนอราคาหลายเวอร์ชัน ส่งมอบพร้อมใบรับประกัน ส่งออก Excel ตั้งค่าร้าน พนักงาน ประวัติการแก้ไข
- กฎของระบบจริงทำงานครบ เช่น เริ่มซ่อมไม่ได้ถ้าราคาล่าสุดยังไม่อนุมัติ ส่งมอบไม่ได้ถ้ายังค้างชำระ ช่างเห็นเฉพาะงานของตัวเอง

## ต่างจากระบบจริงตรงไหน

| ระบบจริง | เดโม |
| --- | --- |
| PostgreSQL กับ trigger ในฐานข้อมูล | IndexedDB ในเบราว์เซอร์ กฎเดียวกันตรวจใน `src/demo/jobs.ts` และคำขอที่ผิดพลาดย้อนข้อมูลกลับทั้งหมดแบบ transaction |
| PDF จาก Gotenberg | เปิดเอกสาร HTML ชุดเดียวกันในหน้าพิมพ์ กดพิมพ์หรือบันทึกเป็น PDF จากหน้าต่างพิมพ์ |
| Excel สร้างที่เซิร์ฟเวอร์ | ExcelJS สร้างไฟล์ในเบราว์เซอร์ คอลัมน์เหมือนกัน |
| เข้าสู่ระบบด้วย LINE (LIFF) | ใช้บัญชี LINE ตัวอย่าง ไม่มีการเชื่อม LINE จริง |
| รหัสปลดล็อกเข้ารหัส AES-256-GCM, argon2 | เก็บในเบราว์เซอร์ของผู้ทดลองเอง รหัสผ่านเก็บเป็น SHA-256 |
| รูปเก็บบน volume ผ่าน URL ที่ลงลายเซ็น | รูปย่อเป็น 1280 px แล้วเก็บเป็น data URL |
| QR พร้อมเพย์เป็นรูปที่ร้านอัปโหลด | QR ตัวอย่างที่มีแค่ข้อความ ไม่ใช่ QR รับเงิน |

## รันและ build

ต้องใช้ Node 20 ขึ้นไป

```bash
npm install
npm run dev       # http://localhost:5190
npm run build     # ได้โฟลเดอร์ dist/
npm run preview   # เปิด dist/ ที่ http://localhost:5191
```

## นำขึ้นเว็บ

`dist/` เป็นไฟล์ static ล้วน ใช้ path แบบ relative กับ hash router จึงวางที่ไหนก็ได้ ไม่ต้องตั้ง rewrite

- Vercel: มี `vercel.json` ตั้งค่าไว้แล้ว (Vite, `npm ci`, `npm run build`, output `dist`, cache ไฟล์ใน assets 1 ปี) ถ้า repo มีหลายโปรเจกต์ ให้ตั้ง Root Directory เป็น `RRTS-Demo` หรือรัน `npx vercel` จากในโฟลเดอร์นี้
- Netlify, Cloudflare Pages: build command `npm run build` และ output `dist`
- GitHub Pages: อัปโหลดเนื้อหาใน `dist/` ไปที่ branch หรือโฟลเดอร์ที่ Pages ใช้ วางใน subfolder ได้
- กล้องสแกนสติกเกอร์ต้องเปิดผ่าน HTTPS (หรือ localhost)

## โครงสร้าง

- `src/demo/server.ts` เส้นทาง API ทั้งหมด สิทธิ์ตามบทบาท และการตรวจข้อมูลด้วย zod
- `src/demo/jobs.ts` งานซ่อมและใบเสนอราคา พอร์ตจาก JobsService และ QuotesService
- `src/demo/seed.ts` ร้านตัวอย่าง ลงวันที่นับจากวันที่เปิดครั้งแรก
- `src/demo/documents.ts` ใบรับเครื่อง A5 และ 80 มม. สติกเกอร์ 50 x 30 มม. ใบเสร็จพร้อมใบรับประกัน
- `src/screens/demo/` หน้าเริ่มต้น แถบเดโม และหน้าพิมพ์
- หน้าจออื่นทั้งหมดมาจาก `web/` ของระบบจริง แก้เฉพาะลิงก์เอกสารให้ไปหน้าพิมพ์ และปุ่มบัญชีเดโมในหน้าเข้าสู่ระบบ
